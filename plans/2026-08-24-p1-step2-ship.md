## 1. 開始前チェック

1. `git switch main && git pull --rebase && git status --short` → 本指示書の untracked のみ。`git branch -D feat/p1-detection-hygiene` はまだしない（merge 後）
2. PR #4 の head が **`20c093e` のまま**であること（`gh pr view 4 --json headRefOid,commits`）。それ以降に commit が積まれていたら**止まって報告**（監督未レビュー）
3. PR #4 の CI（run `32685871849`）が success、mergeable が CLEAN であること
4. `gh run list --workflow=update-news.yml --limit 3` が全て success（cron が壊れていない状態で merge する）

## 2. merge → main push CI

1. `gh pr merge 4 --squash --delete-branch`（タイトルは PR タイトルのまま。本文は §5 の要約 3 行程度）
2. merge commit SHA を記録。`gh run list --workflow=ci.yml --branch main --limit 1` で main push の CI run が success になるまで `gh run watch`
3. `git switch main && git pull --rebase && git log --oneline -3`。ローカルの `feat/p1-detection-hygiene` を `git branch -D` で削除、`git fetch --prune` で remote 側の消滅を確認

## 3. 本番 dispatch（1 回だけ）

1. `gh workflow run update-news.yml` → `gh run watch` で完了まで
2. 記録すること: run ID / 結論 / `update` job の所要時間 / ログの `[FEED FAIL]` `[RANKING FAIL]` の件数と本文 / `Node.js 20` `deprecated` の件数
3. `git pull --rebase` で生成物 commit を取り込み、`docs/status.json` から `generated_at` / `gate` / `feeds` / `rankings` と、**`ok` でない行の name / kind / status / detail を全て**
4. **GIZMODO / FASHIONSNAP / 日経 が `empty` になっても失敗ではない**（実装指示書 §1・§7）。その場合は `detail` と `[RANKING FAIL]` の本文を貼り、実装指示書 D2〜D4 のどのアンカー（タブ対応 / active / 順位番号 / コンテナ / 「総合」「今日」）が無かったかを **推測せず** ログの証拠だけで報告する。パーサを直さない
5. `detail` に URL・パス・`?` 付きクエリ・`Max retries exceeded with url:` が**含まれていない**ことを `grep` で確認（D5 の本番確認）。失敗行が無ければ「失敗行なし、確認対象なし」と書く

## 4. Dependabot PR（#3 → #2 の順、1 本ずつ）

- #3 `chore(deps-dev): bump pytest from 8.3.5 to 9.1.1 in /scripts`（dev 依存のみ）
- #2 `chore(deps): bump the python-deps group across 1 directory with 3 updates`（**ランタイム依存を含む可能性**。merge 後は本番 dispatch で再確認する）

各 PR について:
1. `gh pr view <n> --json mergeable,mergeStateStatus,headRefOid,files` で変更ファイルを記録（`scripts/requirements*.txt` 以外を触っていたら止まって報告）
2. head が main（§2 の merge 後）より遅れていれば PR に `@dependabot rebase` をコメントし、rebase 後の CI run を `gh run watch`
3. **CI green のときだけ** `gh pr merge <n> --squash --delete-branch`。red / conflict / rebase が来ない場合は**止まって報告**（無理に直さない）
4. #2 を merge した場合のみ、`gh workflow run update-news.yml` を**もう 1 回**実行し §3 の 2〜3 を再記録（ランタイム依存の更新が本番で通ることの確認）。#2 を merge しなかった場合は dispatch しない
