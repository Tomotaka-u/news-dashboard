# P1 Step 1 出荷手順（Codex 向け）: ブランチ `ci/p1-safety-net` を PR → CI → merge → 本番 workflow 即時実行 → verify

作成: 2026-08-22（Claude 監督セッション）。対象 commit: `b16e2f3`（ローカルブランチ `ci/p1-safety-net`、未 push）。

## 0. 前提

- ローカル `~/projects/news-dashboard` のブランチ `ci/p1-safety-net` に `b16e2f3` が 1 commit だけ乗っている（`main` = `0149728` から分岐）。作業ツリーは本ファイルを除き clean のはず。`git status --short` と `git log --oneline main..ci/p1-safety-net` で確認してから始める
- 変更内容（4 ファイル）: `.github/workflows/update-news.yml`（checkout/setup-python を v7 へ、push を最大 3 回リトライ）/ `.github/workflows/ci.yml`（新規、docs/ 以外の push・PR で Py3.12 の compileall + pytest）/ `.github/dependabot.yml`（新規）/ `CURRENT_STATE.md`
- 設計・検証は Claude 側で完了済み（YAML パース、bash -n、compileall、pytest 12 passed、checkout v6+ の credential 変更が push 互換であることを README で確認）。**Codex はコードを変更しない**。本指示書は「出荷と本番 verify」だけ
- 目的は 2 つ: (a) PR の `pull_request` トリガーで `ci.yml` を実地テスト（checkout@v7 + setup-python@v7 + 3.12 pytest が動くか） (b) merge 後に本番 `update-news.yml` を `workflow_dispatch` で即時実行し、18:00 JST cron を待たずに v7 で green を確認

## 1. 手順（順番どおり。各ステップの出力を報告に貼る）

1. 本ファイルをブランチに追加して push
   ```
   git add plans/2026-08-22-p1-step1-ship.md
   git commit -m "docs: P1 Step1 出荷手順を追加"
   git push -u origin ci/p1-safety-net
   ```
2. PR 作成
   ```
   gh pr create --base main --head ci/p1-safety-net \
     --title "ci: actions v7 更新・push リトライ・CI pytest と Dependabot 追加" \
     --body-file - <<'EOF'
   P1 バケット①「運用安全網」。

   - update-news.yml: actions/checkout@v7, actions/setup-python@v7（Node 20 deprecation 解消）、push リトライ（rebase → 最大 3 回、競合は exit 1）
   - ci.yml: docs/ 以外の push・PR で Python 3.12 の compileall + pytest scripts/tests
   - dependabot.yml: pip（/scripts）と github-actions を週次
   - CURRENT_STATE.md 更新

   検証: YAML パース / bash -n / compileall / pytest 12 passed（ローカル）。この PR の CI が v7 + 3.12 の実地テスト。
   EOF
   ```
3. CI が終わるまで待って結果を確認
   ```
   gh pr checks --watch
   gh run list --workflow ci.yml --limit 3
   ```
   - **green でなければ merge しない**。`gh run view <run-id> --log-failed` の出力を貼って報告し、ここで停止する（Claude 側で直す）
4. merge（squash、ブランチ削除）
   ```
   gh pr merge --squash --delete-branch
   git switch main
   git pull --rebase
   git log --oneline -3
   ```
   - squash 後の main の commit には Co-Authored-By trailer が残らなくてよい
5. 本番 workflow を即時実行して verify
   ```
   gh workflow run update-news.yml
   sleep 90
   gh run list --workflow update-news.yml --limit 2
   ```
   最新 run の ID を取り、以下を確認して出力を貼る:
   ```
   gh run view <run-id>
   gh run view <run-id> --log | grep -E "Python 3\.|Node\.js 20|deprecat|FEED FAIL|RANKING FAIL|gate|push failed|No changes" | head -40
   ```
   確認項目:
   - ①run が success
   - ②ログに「Node.js 20 is deprecated」が**出ていない**（v7 化の目的）
   - ③`Python 3.12.x` が使われている
   - ④`[FEED FAIL]` / `[RANKING FAIL]` の行があればその内容（0 件なら 0 件と報告。書式確認が目的）
   - ⑤`git pull --rebase` で取り込んだ `docs/status.json` の `generated_at` が今回の実行時刻（JST）に更新されている。`docs/` に差分がなく「No changes in docs/」で終わった場合はそれも正常（直前 cron と同一内容）。その場合は `status.json` は更新されない旨を報告
   ```
   git pull --rebase
   python3 -c "import json; d=json.load(open('docs/status.json')); print(d['generated_at'], d['gate'], d['feeds'], d['rankings'])"
   ```
6. `gh run list --workflow ci.yml --limit 2` で、merge による main への push でも `ci.yml` が走って green か確認（`paths-ignore: docs/**` なので走るはず）

## 2. 禁止事項

- `main` への force push、`--no-verify`、`git add -A`
- `scripts/` `templates/` `docs/` `.github/` のコード・設定変更（赤くなったら報告して止まる。直すのは Claude）
- PR を CI red のまま merge すること
- `update-news.yml` を 2 回以上連続で dispatch すること（concurrency で前の run がキャンセルされ、履歴が読みにくくなる）

## 3. 返却形式（監督が一次証拠で verify するため、以下をそのまま貼る）

```
## 実行した手順と結果（1〜6 それぞれ OK / NG）
## PR URL・merge 後の main HEAD（git log --oneline -3）
## ci.yml run（PR 時と main push 時）: run ID / 結論 / 所要時間
## update-news.yml dispatch run: run ID / 結論 / Python 版 / Node 20 警告の有無 / FEED・RANKING FAIL 行 / status.json の generated_at と gate
## 停止した箇所と理由（あれば）・--log-failed の出力
## 気づいた事項（あれば。修正はしない）
```
